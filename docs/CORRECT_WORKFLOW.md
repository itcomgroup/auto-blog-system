# Правильный Workflow создания статей из Opencode CLI

## ⚠️ ВАЖНО: Не генерировать "с потолка"!

**Неправильно:** ❌
- Использовать Exa API для поиска статей в интернете
- Генерировать вымышленные кейсы и цифры
- Придумывать "личный опыт"
- Создавать теоретические статьи без реальной основы

**Правильно:** ✅
- Брать темы из реальных сессий Opencode CLI
- Использовать реальные команды, код, ошибки и решения
- Создавать статьи на основе реального опыта работы
- Добавлять конкретные примеры из логов

---

## Процесс создания статьи

### Шаг 1: Извлечь идеи из реальных сессий

```bash
npm run extract-ideas-opencode -- --days 7
```

Это проанализирует логи `~/.local/share/opencode/storage/` и создаст `output/ideas-opencode.json` с реальными темами из ваших сессий.

### Шаг 2: Выбрать тему из реальных сессий

Посмотреть список тем:
```bash
cat output/ideas-opencode.json | jq '.ideas[].topic'
```

Выбрать тему с:
- Высокой сложностью (4-5)
- Конкретными технологиями
- Реальными командами и решениями

### Шаг 3: Найти исходную сессию

```bash
ls ~/.local/share/opencode/storage/session/global/
```

Найти сессию по названию или дате. Просмотреть содержимое:
```bash
cat ~/.local/share/opencode/storage/session/global/ses_XXXXX.json | jq '.'
```

### Шаг 4: Извлечь реальные команды и код

Из сессии извлечь:
- Команды bash
- Конфигурационные файлы
- Ошибки и их решения
- Код и скрипты
- URL и API endpoints

### Шаг 5: Создать статью

Использовать `npm run generate-post` с контекстом из реальной сессии:

```bash
npm run generate-post "Название темы" --context="$(cat session_content.txt)"
```

## Структура правильной статьи

### 1. Введение
- Реальная проблема из сессии
- Контекст: что делали и зачем

### 2. Основная часть
- **Конкретные команды** из логов (не общие примеры)
- **Реальные ошибки** и их решения
- **Файлы конфигурации** с полными путями
- **Версии** ПО (версии из сессии)

### 3. Практический пример
- Код, который реально работал
- Полные команды с флагами
- Результаты выполнения

### 4. Выводы
- Что получилось
- Какие проблемы решены
- Ссылки на реальные ресурсы

## Пример правильной статьи

```markdown
# Настройка MiniMax M2.1 через NVIDIA NIM API

## Введение

При работе с auto-blog-system нам нужно было переключиться с LLaMA 3.1 
на MiniMax M2.1. Процесс занял 2 часа отладки из-за таймаутов и 
неправильных endpoints.

## Проблема

Изначально модель `minimaxai/minimax-m2_1` возвращала 404 ошибку 
через стандартный API endpoint.

## Решение

Правильный model ID оказался: `minimaxai/minimax-m2.1`

```bash
# Тестирование модели
curl https://integrate.api.nvidia.com/v1/chat/completions \
  -H "Authorization: Bearer $NVIDIA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "minimaxai/minimax-m2.1",
    "messages": [{"role": "user", "content": "test"}],
    "max_tokens": 50
  }'
```

## Результат

MiniMax M2.1 заработала, но требует таймаут 30 минут для генерации 
статей (вместо 2 минут у LLaMA).
```

## Важные файлы

- `~/.local/share/opencode/storage/session/global/` - сессии
- `~/.local/share/opencode/storage/message/` - сообщения
- `output/ideas-opencode.json` - извлечённые темы
- `SESSION_LOG.md` - лог сессий (если ведётся)
